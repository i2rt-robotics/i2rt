## 二、工作点

### 2.1 `kinematic`

```
--transport ethercat --loop-hz 500 --max-torque 18 --gain-scale 5.0 --motor-kd 5.0
```

在五个起始位姿上验证,`cond(J)` 14.8–43.1:

| 位姿 | cond(J) | 峰值 \|dq\| | 静置 rms |
|---|---|---|---|
| 基线 `0,45,20,-60,0,30,0` | 17.1 | 1.75 rad/s | 0.0027 |
| 伸展 `0,20,0,-25,0,20,0` | 43.1 | 0.73 | 0.0028 |
| 收拢 `0,70,30,-95,0,30,0` | 14.8 | 1.84 | 0.0011 |
| 侧向 `-40,50,35,-70,20,35,0` | 15.9 | 1.28 | 0.0016 |
| 腕部翻转 `0,45,20,-60,60,30,40` | 17.8 | 0.94 | 0.0014 |

**刚度与电机阻尼是一个旋钮。** 主机侧 kd 被编码器量化封顶,每提一档刚度,缺的阻尼必须转到电机:

| `--gain-scale` | `--motor-kd` | 最差关节 | 判定 |
|---|---|---|---|
| 2.0 | 2.0 | j7 1.94 rad/s | 稳 |
| 3.0 | 3.5 | j7 1.37 | 稳 |
| 4.0 | 4.5 | j7 1.09 | 稳 |
| 5.0 | 5.0 | j6 1.75 | 稳 |

`--motor-kd` 被固件钳在 5.0,所以 5.0x 是这条链路的上限。

**上限由腕部静摩擦决定**,不是控制律或总线:

| | j1 | j2 | j3 | j4 | j5 | j6 | j7 |
|---|---|---|---|---|---|---|---|
| 静摩擦 (N·m) | 1.91 | 1.37 | 1.18 | 0.46 | 0.29 | **0.04** | 0.10 |
| 刚度封顶对应 gain-scale | 37.6x | 26.9x | 23.2x | 12.1x | 15.2x | **2.1x** | **5.2x** |

超过约 5x 只加硬 j1–j5,腕部不变,代价是静置噪声上升(2x→4x:rms 0.0011 → 0.0058 rad/s)。

### 2.2 `full`

```
--transport ethercat --loop-hz 500 --max-torque 18 --gain-scale 4.0 --cart-zeta 1.0 --motor-kd 5.0
```

三个旋钮都探到两侧边界:

| 旋钮 | 试过 | 回位残差(占推开幅度) |
|---|---|---|
| `--gain-scale` | 2.0 / 3.0 / **4.0** / 5.0 | 32% / 23% / **11%** / 17–49% |
| `--cart-zeta` | 0.7 / **1.0** / 1.4 | 23% / **11%** / 21.8 Hz 持续极限环 |
| `--motor-kd` | 全程 5.0 | 不需随刚度配平 |

`Kp6 = 40 × gain-scale`,量纲 1/s²,任务带宽 `√Kp6`。残差随推开幅度增大:78 mm 回到 1 mm,
112 mm 剩 13,111 mm 剩 18 —— 增益是按保持位姿做的惯量整形。

### 2.3 两个模式

| | `kinematic` | `full` |
|---|---|---|
| 手推肘部行程 | 8–9° | **27–30°** |
| 每度肘部 → 末端 | 4.9–11.7 mm | **1.5–2.2 mm** |
| 耦合线性度 R² | 0.47–0.63 | **0.80–0.93** |
| 推开后回位 | **4–7%** | 11–12% |
| 峰值力矩用量 | 18.0 / 18 N·m | 10.4 / 18 N·m |
| 增益的位姿依赖 | 无 | 在单一位姿上整形 |
| 对惯量模型误差 | 免疫 | 直接敏感 |

仿真预测 `kinematic` 18 mm/deg、`full` 1.7 mm/deg。**要用手引导肘部、末端保位 → `full`;
要末端刚性抗扰 → `kinematic`。**

## 三、P0 必填三项(§4.1)

### 3.1 单电机反馈率

| 总线 | 实测 | 测法 |
|---|---|---|
| EtherCAT-to-CAN | **500.0 Hz** | `--stage survey` |
| USB-CAN | 282.6 Hz | `--stage survey` |

三个不同的速率,只有一个用来降额:

| 层 | 速率 |
|---|---|
| 桥的 EtherCAT tick | 1 kHz |
| CAN 侧单电机刷新 | 428.5 Hz(3/7 × 1 kHz),最差间隔 3.00 ms |
| **桥的 DDS 发布** | **500 Hz,七个电机打包成一条消息** |

主机看到的是第三个,七个关节全部 500.0 Hz。**降额用这个数**:主机在这个速率上做位置差分,
量化噪声在这里注入。作为 `--loop-hz` 传入。

### 3.2 组间时间偏斜

| 总线 | 均值 | p99 | 最大 |
|---|---|---|---|
| EtherCAT-to-CAN | **0.00 ms** | 0.00 ms | 0.00 ms |
| USB-CAN | 2.59 ms | 3.07 ms | 5.56 ms |

七个电机在同一条 DDS 消息里到达。**仿真里建模的"三个一组轮询偏斜"在这条链路上不存在**,
速度观测器的逐关节外推在这里是空转的(它是为 USB-CAN 台架准备的)。

### 3.3 下发是否分批

**是。** 每个 CAN2EtherCAT 从站的过程数据是 86 字节 = `2 + 6 × 14`,六个原始 CAN 帧槽,
每通道三个。一次算出的七维力矩分两到三个周期下发,不同关节的力矩作用时刻相差最多 2 ms。

### 3.4 环路抖动

| 环 | 均值 | p99 | 最大 |
|---|---|---|---|
| Python 控制环(`--stage jitter`) | 2.000 ms | **2.831 ms** | 3.102 ms |
| EncosBridge 复现(C++,1 kHz) | 0.052 ms | — | 0.076 ms |

C++ 侧 10000 个周期,WKC 短缺 0 次,循环率 999.9 Hz。

### 3.5 DDS 传输

| QoS | 速率 | p50 | p99 | max | 超两倍标称 |
|---|---|---|---|---|---|
| best-effort, depth 1 | **500.0 Hz** | 2.00 ms | **2.08 ms** | 2.17 ms | **0 / 10000** |
| reliable, depth 1 | 500.0 Hz | 2.00 ms | 2.12 ms | 2.68 ms | 0 / 9999 |

小包(七个 float)、`ROS_LOCALHOST_ONLY=1`、Fast DDS 共享内存。量的是**间隔稳定性**,
p99 与 p50 几乎重合,传输没有引入可变延迟。话题降频本身带来最多 2 ms 的固定数据年龄。

臂静止时 `identical consecutive payloads: 9999/9999` —— 话题里没有每电机新鲜度信息,
单电机掉线检测由 `state_working` 提供。

## 四、链路参数

| 项 | 值 |
|---|---|
| 从站数量 | 5,全部 `CAN1MOTOR`,vendor `0x00000002` product `0x00010000` |
| 每从站过程数据 | 86 字节进 / 86 字节出 |
| 组 0 合计 | 430 字节 |
| 工作计数器 | 期望 15,每周期满分 |
| 电机接线 | 七个全在 slave 0 / channel 1 |
| 网口 | `enp99s0`(Intel I226-V) |

**接入要求:每个电机 `MASTER_ID == ID`。** 板子固件按"朝哪个 ID 发就等哪个 ID 回复"填充应答槽,
而 i2rt 默认刷成相差 16。不满足时五个从站全部进 OP、工作计数器满分,**CAN 侧零回应** ——
与电源没开、波特率不对、CANH/CANL 接反完全一样。用 `ecat_setid --write` 刷写并断电重启验证。

连带后果:USB-CAN 那条路要带 `--receive-mode same`。`get_robot.py` 保持 `p16`,那是 6-DOF YAM
臂的工厂函数。

**桥需要打补丁**才能接受力矩:`humanoid_internal` 分支 `yihan/7dofarm`。没有 `/motors/cmd_torque`
的订阅,`ff_` 永远是 0,MIT 律只剩阻尼项。

**桥的安全模型与 CAN 不同:** 它每 1 ms 重发收到的最后一条命令,没有任何超时。进程被杀,
手臂一直握着最后那组力矩和增益。释放是客户端的责任 —— `EtherCatChain.close()` 发三次零力矩,
`_safe_teardown` 屏蔽 SIGINT 让释放先完成。

**桥的 stall watchdog 会逐电机锁存**(`state_working` bit 0x08,单向,只有重启桥能清)。
被锁的电机仍正常上报位置,所以 `DRIVE_FAULT_BITS` 必须包含 0x08,否则它看起来一直健康。

## 七、仿真与真机的差异

1. plant 与控制器共用同一 MJCF,模型误差为 0。
2. 无传动摩擦、无 cogging。真机上"放手能不能停住"由摩擦决定,仿真结构上答不了。
3. 电机侧 kd 在仿真里作用于干净速度,真机上是固件自己的差分值。
4. 仿真建模的三组轮询偏斜在 EtherCAT 链路上不存在(实测 0.00 ms)。
